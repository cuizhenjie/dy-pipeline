# OMNI 全域营销运营 Agent 平台（DSH 工作台插件）

`dsh-workbench-omni-marketing` 是一个自包含的 DSH 工作台插件，提供全域营销运营面板：

| 模块 | 能力 |
| --- | --- |
| 营销 Dashboard | 全域 KPI、30 天 GMV/消耗趋势、渠道对比、转化漏斗、今日待办 |
| 渠道管理 | 抖音 / 微信公众号 / 小红书 / 快手 / 视频号 / 微博的授权与经营状态 |
| 营销活动 | 活动列表、状态筛选、新建活动、启动 / 暂停投放 |
| AI Agent 编排 | 内容生成 / 投放优化 / 智能客服 / 数据分析 Agent，任务下发与运行记录 |
| 素材库 | 素材卡片、类型筛选、待审核素材的通过 / 驳回 |
| 全渠道发布 | 一次创建、多渠道分发，立即 / 定时发布，失败渠道重试 |
| 线索 / 客户 | 线索列表、来源渠道、阶段流转、阶段分布图 |
| 数据报表 | 渠道与活动报表、汇总指标、CSV 导出 |

设计体系见 [DESIGN.md](./DESIGN.md)。样式只使用宿主 `--dsw-alias-*` 语义 token，文案中英文同批维护，响应式基于业务容器宽度的双层容器查询。

## 数据与边界

- 当前数据为**种子数据 + 本机持久化**（`$DSH_HOME/omni-marketing/data.json`），用于业务链路演示与验收；写操作（新建活动、发布任务、阶段流转等）会真实落盘并在重启后保留。
- **未接入真实渠道**：授权、投放、发布均为状态模拟，不会对真实平台产生副作用。接入真实渠道 API 是后续工作。
- AI Agent 的任务下发记录为本地模拟执行；需要真实生成能力时，通过面板右上角「AI 助手」使用宿主原生会话。

## 开发

```bash
pnpm install --no-lockfile   # 安装构建与测试依赖（不产生竞争锁文件）
pnpm build                   # JSX -> lib/client.js（构建产物，不入库）
pnpm test                    # 构建 + 服务端行为回归 + 客户端 SSR 渲染回归
pnpm pack                    # prepack 自动构建，产出安装 tarball
```

- `dsh/`：服务端（`ctx.connection.fetch.register` 暴露 `/api/omni-marketing.*`）。
- `src/client/`：客户端源码。React 由宿主模块加载器在 factory 中注入，源码不顶层依赖 React。
- `test/`：`node:test` 行为回归（API 状态机、持久化、8 页 SSR 渲染、注册协议、文案 key 同步）。

## 本机安装与验收（需要在 DSH Desktop 环境执行）

```bash
pnpm pack
dsh workbench import ./dsh-workbench-omni-marketing-0.1.0.tgz
```

验收清单：

1. 工作台出现「OMNI 全域营销」，打开后显示 Dashboard，工具栏为紧凑模式。
2. 八个模块切换正常，loading / 空态 / 错误态可见；断网或停服务端时显示错误重试。
3. 新建活动 → 列表出现草稿 → 启动投放 → 状态变为投放中；重启应用后数据仍在。
4. Agent 卡片下发任务 → 运行记录新增成功条目。
5. 素材库审核「待审核」素材 → 状态更新；「让 AI 生成素材」打开 AI 助手会话。
6. 全渠道发布：勾选微博（未授权）→ 该渠道标记失败 → 重试给出授权提示；其他渠道显示已发布。
7. 线索阶段下拉流转 → 右侧分布图同步变化。
8. 数据报表导出 CSV → 文件可打开且中文无乱码（含 BOM）。
9. 响应式：收窄窗口与收起侧栏，导航折叠为图标栏、卡片网格降列、表格内部横向滚动，无整页横向溢出、无单字竖排。
10. 切换中英文与深浅主题：文案完整、颜色跟随宿主 token。
